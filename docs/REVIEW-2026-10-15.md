## Findings and fixes

| Finding                                                                             | Change and regression evidence                                                                                                                                                                                                                                                                                                       |
| ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Missing remote IDs could become invented confirmations                              | Remote ticket and annotation IDs are required, nonempty, whitespace-free identifiers. Only the mock domain creation generates them. Six contract regressions failed first. Four integration cases lose or empty the ID after a real HTTP commit, observe unknown state, then recover the original effect through its actual journal. |
| Response limits applied after downloading; activity timeouts could stall the worker | Requests stream under a 32 KiB cap and enforce total deadlines: two seconds for reads, three seconds for mutations/journal reads. Only identity encoding is accepted. The entire model tool loop has a 120-second deadline, including awaited tools. Oversize, continuous-stream and stalled-tool regressions failed first.          |
| Late browser responses could replace newer selections/state and lose a retry        | Selection generations ignore superseded responses. A per-case cache retains the highest observed version in active and inbox views. Selection preserves a failed mutation's saved body/key. Three component regressions failed first and now cover these behaviors.                                                                  |
| Termination during startup could orphan detached children                           | Termination handling is installed before launch. SIGTERM/SIGINT are deferred during spawn and ownership registration, then startup cleanup handles the pending interruption. Two real supervisor regressions interrupt readiness and the exact spawn-before-registration boundary; both failed before their respective fixes.        |
| Metadata failure could strand the shared model lock                                 | Process metadata is prepared before acquisition. Partial owner-file failures clean only the directory/file identities created by that acquisition. Metadata and process-inspection regressions failed first. Existing foreign-owner protections remain.                                                                              |
| A recent recorded scan could contradict an old last-event timestamp                 | Naive, future or newer-than-summary carrier event timestamps require manual review. Three development regressions failed first. Frozen scenarios were not modified.                                                                                                                                                                  |

The same reviewer checked these fixes and identified the narrower spawn-before-registration race during follow-up. That race received its own failing process regression. An initial signal-mask approach was rejected because children inherited blocked termination signals. The final implementation defers only the supervisor handler, and the strengthened regression rejects SIGKILL escalation. The reviewer closed all six findings after inspecting that final delta. Execution remains author-verified; the reviewer did not independently run the full suites or actual model.
