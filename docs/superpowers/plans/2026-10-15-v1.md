## Review focus

- A process dies after a remote commit but before its response is saved: reconcile the same key and preserve one side effect (Tasks 2, 6, 9).
- Approval, cancellation and a second worker race: transactionally select one outcome and fence local updates (Tasks 5, 6, 9).
- A carrier/order/policy changes after proposal creation: stale approvals fail and post-ticket conflicts remain visible (Tasks 5, 6, 9).
- Tool text requests another customer's order or a privileged write: reject the requested capability before dispatch (Tasks 3, 4, 10).
- A browser retries after a lost response, including in dark/mobile/reduced-motion modes: replay the same decision key and show the true state (Tasks 7, 8, 9).
